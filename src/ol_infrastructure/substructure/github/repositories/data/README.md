# Repository fleet data

Generated by `bin/github-org-inventory crawl`, one file per repo in `repos/`. Each file
declares only what that repo **deviates** from its archetype on, so `git diff` over this
directory shows exactly the drift and nothing else. See
`docs/plans/github-org-pulumi-import.md` §3.2.

Regenerate:

```sh
uv run bin/github-org-inventory crawl --refresh
```

## Reading this data

- `archetype:` names a shape in `archetypes.yaml`. Everything not stated is inherited.
- Keys prefixed `_` are **inventory, not configuration** — they are recorded so a decision
  stays visible, and no Pulumi resource is generated from them:
  - `_excluded_environments` — how many `RepositoryEnvironment`s were deliberately NOT
    imported (§4.3). 7,803 exist org-wide; importing them guarantees a churning diff.
  - `_actions_secret_names` — secret **names** only. Values are write-only and are never
    imported (§4.1).
- These files record what each repo **is today**, deviations and all, including where
  today's value is wrong. That is deliberate: §6's empty-diff gate requires the model to
  match reality before phase 5 changes anything. A wrong-but-explicit value is an
  auditable finding; a silently-corrected one is an unreviewed production change.

## One trap: `.github.yaml` is a dotfile

The org's `.github` repo generates `repos/.github.yaml`. **A shell glob or `glob.glob()`
will silently skip it**; `pathlib.Path.glob()` will not:

```python
len(list(Path("repos").glob("*.yaml")))   # 316  <- correct
len(glob.glob("repos/*.yaml"))            # 315  <- silently drops .github
```

Any loader here must use `pathlib`, or enumerate with `iterdir()` and filter on suffix.
The failure mode is one repo quietly absent from the stack, which looks identical to a
repo nobody has gotten to yet.
